# Town Drive Unity migration module

This module starts Town Drive's migration into the existing `unity/SpaceDragon` project. It contains the measured route/context export, an engine-independent C# driving core, Unity JSON loading and parity tests. It does not yet contain the playable Unity scene, detailed art, input/camera bindings, traffic/pedestrian simulation or persistence adapter.

The shared Unity channel owns the project's `ProjectSettings`, packages, renderer and other scenes. Those prerequisites must accompany this module for Editor tests. The portable C# checks work independently of that project setup. Do not create another Unity project or run an Editor while the shared project is in use.

## What is preserved

- Verified SD-085 metre-scale route, including Starpass → Green Island → Winston Trails South → Hypoluxo, divided-road midpoint and shared cul-de-sac return.
- Fixed 60 Hz simulation, assist/reverse/handbrake behavior, forgiving collision/recovery, ordered checkpoints and idempotent loop completion.
- Double-precision state and one presentation interpolation contract for a future car/camera binding.
- Versioned context JSON with four mapped lake outlines, 83 estimated lots, eleven closures, 278 closure collision discs, source hashes and OpenStreetMap attribution. The pure driving DTO intentionally leaves scenery to its future presentation adapter.

No browser or campaign save is read or migrated by this module. Candidate persistence is a later adapter, not an automatic consequence of retaining checkpoint IDs.

## Reproduce the checks

From the repository root with Node 24 and the .NET 8 runtime/targeting pack (a newer SDK may compile it):

```powershell
node --experimental-strip-types tools/unity/export-town-drive.mjs --verify
dotnet run --project tools/unity/town-drive-parity/TownDriveParity.csproj --configuration Release
```

The exporter rejects drift from the recorded SD-085 source fingerprint. Its known fingerprint pins the historical source revision, so a documentation-only commit does not change generated bytes. `--source-root`, `--output-root`, `--compare-source-root`, `--expected-fingerprint` and `--source-revision` support a deliberate later migration snapshot. Review changed source and fixture results before accepting a new baseline. The data lives in `Data` for an explicit future Town Drive scene reference; golden test fixtures live under editor-only tests. Neither is a global Resources payload added to unrelated Unity player builds.

With the existing shared Unity project available and its Editor idle:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/unity/run-town-drive-tests.ps1
```

That command runs only the two Town Drive EditMode test assemblies and writes fresh logs/results under `artifacts/unity-town-drive`. It does not generate a scene or change the shared build list. Passing .NET tests, Unity EditMode tests, actual player builds and driving/visual acceptance are separate evidence.

## Binding boundary

`TownDriveJson.Load(TextAsset)` validates the scene's explicit data reference using Unity's serializer; `Parse(string)` supports a host-provided JSON source. Construct `DriveRoute` and `DriveSimulation` from it. Supply semantic `DriveInput` at exactly 1/60 s; keep bounded frame accumulation in the eventual runtime adapter. Use `DrivePresentation.Interpolate` for car and camera together, snapping both on reset/pause/discontinuity. Rendering and animation must not advance checkpoints or write saves.

The [visual/behavior handoff](../../../../../docs/engineering/UNITY_TOWN_DRIVE_HANDOFF.md) describes reuse of the existing detailed world and minivan. Keep the browser Drive Lab available until the Unity replacement has passed the [migration receipt](../../../../../docs/reports/2026-10-31-unity-town-drive-foundation.md) and the later scene/player checks.

## November 1 surface and landscape pass

Town Drive owns scanned CC0 roof/stucco inputs in `Art/v002` and reproducible surface, roof and garden derivatives in `Generated`. Physical UV mapping preserves imported positions, indices, normals and bounds. Low planting adds no colliders or game state. Six scene tests cover the original integration and new persisted art. See the [art receipt](../../../../../docs/reports/2026-11-01-town-drive-surface-art.md) for build/player evidence, source provenance and visual limits.

## Foliage, facades and cabin — v003

Fuller authored palm crowns replace only visible source leaves at their existing anchors; original parts remain for rollback. Spatially batched facade trim and cabin microstructure are separate native derivatives. A single low-resolution rear-camera-style mirror captures at most six times per second, only in visible unpaused cabin view. Ten scene tests and expanded actual-player checks cover this increment; see [the v003 receipt](../../../../../docs/reports/2026-11-01-town-drive-foliage-cabin.md).
