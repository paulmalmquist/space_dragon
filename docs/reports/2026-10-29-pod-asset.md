# Rescue pod asset pipeline

Date: October 29, 2026. Status: locally IMPLEMENTED and technically VERIFIED; provisional design, human art review pending. No likeness is used or approved by this work.

## Scope and environment

The owner asked for the first real pod asset through Blender → GLB → compressed textures → the actual browser scene, with measurements. Blender MCP returned “Could not connect to Blender”; its live scene was not changed. The installed Blender **5.2.1 LTS** instead ran in a new isolated background process using the reviewable [build script](../../tools/build-pod.py). The script refuses a live/loaded scene and refuses an existing output version. No photo, external generator, downloaded model, or family recording was used.

The source is an original provisional engineered rescue chest. Its articulated lid, panel seams, status lamps, non-letter symbol, and safety latches establish a usable asset contract; this is not approved final dragon technology or final artwork. Blender coordinates are meters. The game export retains `pod_root`, `hinge_pod_lid`, `pod_lid`, and a `pod_open` clip.

| Chromium actual game load, explicit SwiftShader | PASS | Pod loads **623.2 ms** in this local automation sample; all 38 meshes/5 materials/one texture/clip observed. Zero page errors, failed requests or external-network requests. |
| Chromium default-renderer probe | PASS; hardware coverage unavailable | Pod loads **2,386.1 ms** in a separate local sample. Browser still reports ANGLE/SwiftShader, not the AMD GPU; no real GPU performance claim. |
| In-scene visual/animation check | PASS | The actual game shows the textured chest and open lid during suit introductions; screenshots retained locally. Human final-art review remains pending. |

Browser checks ran on this Windows Lenovo 82XM with Playwright Chromium, WebGL 2. They are integration/compatibility samples, not loading budgets, a 60 fps pass, physical-device testing, or the requested ten-minute family playtest. Software frame timing is deliberately not promoted to a target-device result.

An initial ad hoc review harness mixed raw and Vite-optimized Babylon modules and was discarded after it produced duplicate-module shader/decoder errors. The passing checks above used the actual game entry point and its normal module graph. The runtime's self-hosted decoder requests were observed directly; it did not fetch a Babylon CDN decoder.

## Repeat and review

Use a fresh version number to preserve source history. Put the installed KTX binary directory on the task's PATH before the compression command. The decoder is built from the official `@babylonjs/ktx2decoder@9.33.0` tarball after checking its npm SHA-512 integrity; all decoder code/binaries and licenses are self-hosted. [Decoder notes](../../public/assets/pod/decoder/README.txt) and the manifest record provenance.

The public runtime folder is an explicit local game-asset candidate under this task. No game deployment, final art approval, new hosting service or repository publication is implied. The editable `.blend`, original PNG and review renders remain local. The parametric build script is the reviewable source recipe for another machine.
